### 今回の絞り込み

顧客ヒアリング管理は「顧客の管理」そのものであり、メディア・マッチング・決済・ログイン・お客さん側からの入力のいずれにも該当しないため、絞り込みは不要と判断。**顧客ごとの課題・仮説・ヒアリング結果・状態を、担当者本人が登録して探して更新する一覧ツール**として組み立てる。

### 1. 今その人はどうやっているか

🔮 顧客ヒアリングの内容を、案件一覧はExcel、面談中のメモは手元のノートやOneNote、社内共有はTeamsのチャットや添付ファイルと、記録場所がバラバラになっており、状況を確認するたびに複数のツールを開いて探し回っていると思われる。
→ 確かめ方: 「今、顧客ごとのヒアリング内容はどこに、どんな形で残していますか？」

### 2. かかっている時間 / 費用

🔮 1社の現状（課題・前回のやり取り・次のアクション）を思い出すために、Excel・メモ・Teamsを横断して探すのに1回あたり15〜20分程度かかり、新規事業として同時並行で20社前後を追いかけているとすると、月あたり5〜7時間程度が「情報を探す」だけに費やされていると思われる。
→ 確かめ方: 「1社の状況を整理し直すのに、だいたい何分くらいかかっていますか？」

### 3. なぜ今まで誰も作らなかったのか

- [x] データが散っている

🔮 ヒアリング情報がExcel・個人のメモ・Teamsのチャットなど複数の場所に自然発生的に増えていき、それらを1つの一覧にまとめ直すには過去分の手入力が必要になるため、後回しにされ続けてきたと考えられる。

### 4. 出口 ── ① 誰が払うか

🔮 使う人（新規事業担当者本人）と払う人（その人が所属する新規事業部・経営企画部）はほぼ一致すると思われる。中堅〜大企業の新規事業部門は、業務効率化のための少額SaaS（月数千円〜数万円程度）であれば、部門予算の裁量で契約できる商習慣があることが多いと推測される。
→ 確かめ方: 「このようなツールがあったら、部署の予算やご自身の裁量で契約できそうですか？稟議は必要ですか？」

### 4. 出口 ── ② どう届くか

🔮 新規事業担当者は横のつながり（社内他部署からの紹介、新規事業系のコミュニティや勉強会、同業の担当者同士の口コミ）で新しいツールの情報を得る傾向が強く、**下の経路（紹介・口コミ・既存の担当者コミュニティ内での直接接触）が主で、検索広告のような上の経路は効きにくい**と考えられる。
→ 確かめ方: 「普段、業務で使う新しいツールや便利な仕組みはどうやって見つけていますか？」

### 4. 出口 ── ③ 受け取れるか

確認した内容: 投資・金融／医療・健康／サプリ・美容／法律相談／暗号資産／ギャンブル／アダルト／情報商材・副業のいずれにも該当しない、社内向けの顧客情報管理ツールであり、決済や審査を要する業種ではない。
🔮 ただしヒアリング内容には顧客の個人情報・商談情報が含まれる可能性が高いため、外部サーバーに送信せず端末内（localStorage）に閉じる設計とすることが前提になると思われる。
→ 確かめ方: 「ヒアリング内容には、社外に出せない情報（個人情報・金額など）はどのくらい含まれますか？」

### 競合には必ず「DIY」を入れる

- **既存の競合**: Excel／Googleスプレッドシート、Notion、Salesforce・HubSpotなどの汎用CRM（多機能すぎて新規事業担当者1人には過剰）
- **DIY競合**: 顧客自身がChatGPTやClaudeに「顧客ヒアリング管理ツールを作って」と頼んで自作する、またはNotionの既製テンプレートをそのまま流用する
- 🔮 **選ばれる理由**: 業務フローに合わせて最初から「課題・仮説・ヒアリング結果・状態」という新規事業のヒアリングに特化した項目で一覧化されており、DIYで毎回ゼロから項目設計し直す**時間**を省ける点にあると思われる。
  → 確かめ方: 「もしChatGPTに頼んで作るとしたら、どんな項目で作りますか？」

## 3. やらないこと

- 複数人でのリアルタイム共有・アカウントごとのログイン機能（今回はlocalStorageによる個人利用のみ）
- 顧客からの直接入力・顧客向けの公開ページ（社内の担当者だけが使う管理画面）
- ヒアリング内容の自動要約・AI分析などの生成AI機能（まずは一覧で状況を把握できることを優先）
